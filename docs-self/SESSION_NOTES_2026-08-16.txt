WHAT THE SESSION WAS ABOUT
The dual-track documentation generator (dual_track.py) was overhauled after
its output on a prior job (the ERR-UI-004 document, and the 2026-08-15
documentation session where rendering was skipped entirely) showed eight
distinct failure modes. The fixes were made earlier today, the script grew
to 3283 lines, and the folder was then turned into a git repository and
published to https://github.com/gorillanobakaa-dot/dual-track-doc-generator.

THE EIGHT GAPS CLOSED TODAY (full rationale is in README.md, same commit)
1. Added a whole new "session" mode: document WORK DONE in a directory
   (git diff + git log + narrative file), not the current code state.
   Schema fields: before_state, after_state, tried_and_abandoned,
   claimed_but_not_verified, open_items.
2. Added get_prior_doc_context(): prior STATUS*/PROGRESS*/GAP*/AUDIT* docs
   in the target directory are injected into every prompt so the model must
   confirm, correct, or supersede prior claims instead of ignoring them.
3. Separation score now checks ideas, not just syntax: a second check scans
   the layman big_picture for developer-vocabulary density (>6 terms
   penalised); the two checks cap at 6 points each.
4. Added BANNED_SELF_CONGRAT: 18 patterns catching self-congratulatory
   narration ("triumph", "neutralizing", "I proved", "flawlessly") that the
   marketing-phrase list never caught. Reported separately from marketing.
5. Validation became the default on all render commands (--no-validate to
   opt out); the then_run hint in prep files now includes --validate.
6. worst_case prompt rewritten to demand a concrete, named harm with an
   example, banning "incorrect results" as a catch-all.
7. design_rationale field renamed known_alternatives; the prompt now forbids
   inventing rationale not present in source comments — absence must be
   stated as "Not available in the source material."
8. Claim-sourcing instruction reversed: entries are for CONCLUSIONS and
   ASSESSMENTS (reasoning), not raw quoted facts; a list containing only
   stated_in_input entries is called out as a red flag.
